## Мета

Створити Flutter-застосунок, навчитися оновлювати стан інтерфейсу, будувати динамічний список, розділяти код на файли та перевіряти поведінку за допомогою тестів і інструментів Flutter.

## Що реалізовано

| Вимога | Реалізація |
|---|---|
| Кнопки «+», «−», «Скинути» | Додавання одиниці, віднімання одиниці, повернення до нуля |
| Останні 10 дій | Модель обмежує історію десятьма записами; найновіший відображається першим |
| Час кожної дії | Локальний час пристрою у форматі HH:mm:ss |
| Заборона від'ємного значення | При натисканні «−» на нулі — SnackBar; значення не змінюється |
| Кратність 10 | Картка має інший колір і пояснювальний напис при `value % 10 == 0` |
| ListView.builder | Заголовок і записи будуються в одному прокручуваному списку |
| Окрема модель історії | Незмінний клас `HistoryEntry` у власному файлі |

**Уточнення поведінки:** нуль також кратний 10. Заблокована спроба віднімання не додається в журнал, бо значення не змінюється. «Скинути» є явною дією користувача: вона записується навіть як 0 → 0. Скидання не очищає історію. Стан зберігається лише в пам'яті; після перезапуску лічильник дорівнює нулю, історія порожня. Збереження на диску умовою не передбачене.

## Структура

| Файл | Призначення |
|---|---|
| `lib/main.dart` | Точка входу, тема та MaterialApp |
| `lib/screens/counter_screen.dart` | StatefulWidget, кнопки, SnackBar, ListView.builder |
| `lib/models/history_entry.dart` | id, дія, попереднє та нове значення, дата/час |
| `lib/models/counter_model.dart` | Значення, правила переходів, обмежена історія |
| `test/counter_test.dart` | Перевірки моделі та граничних умов |
| `test/widget_test.dart` | Кнопки, повідомлення, колір і малий екран |
| `tool/capture_screens.dart` | Відтворювані зображення через Flutter widget-тест |
| `docs/` | Результати перевірок та зображення |

Модель створюється один раз у `initState()`, а не при кожному `build()`. Зміни виконуються у `setState()`. Історія доступна через незмінне представлення, щоб зовнішній код не порушив обмеження. Окремий ідентифікатор запису дозволяє розрізняти дії, зроблені в одну секунду.

У застосунку немає TextEditingController, Timer, власних Stream чи підписок, тому ресурсів для ручного закриття в `dispose()` немає. ListView і ScaffoldMessenger керують своїми внутрішніми ресурсами. Порожнє перевизначення `dispose()` не додавалося.

## Запуск

Перевірене середовище: Flutter 3.35.5, Dart 3.9.2. Потрібні Flutter SDK у PATH, Android Studio, Android SDK, Command-line Tools та емулятор.

```bash
flutter doctor --android-licenses
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run -d DEVICE_ID
```

Замість `DEVICE_ID` — ідентифікатор із `flutter devices`. Запустіть Android-емулятор через Device Manager. Для телефона ввімкніть USB debugging і підтвердьте доступ комп'ютера. Помилки doctor, що стосуються Android, необхідно усунути до здачі.

Додатковий запуск у Chrome та вебзбірка:

```bash
flutter run -d chrome
flutter build web
```

Мережа для роботи лічильника не потрібна. Вебперевірка не замінює потрібної демонстрації на емуляторі.

## Алгоритм

1. Після відкриття створюється модель зі значенням 0 і порожньою історією.
2. Натискання «+» або дозволене «−» визначає нове значення.
3. Модель додає на початок запис із часом, дією та переходом «було → стало».
4. Якщо записів стало більше десяти, найстаріший видаляється.
5. Flutter перебудовує екран; колір картки залежить від кратності 10.
6. На нулі кнопка «−» залишається доступною для демонстрації повідомлення, але зміна не виконується.

| Натиснути «Скинути» | 0, новий запис скидання, попередні записи залишаються в межах ліміту |
| Збільшити системний шрифт | Кнопки переносяться завдяки Wrap, список прокручується |

## Hot Reload та Hot Restart

Наведено план досліду й очікувані результати за документацією Flutter. Фактичний дослід на Android потрібно виконати самостійно: у середовищі підготовки немає Android-емулятора чи телефона.

1. Запустіть debug-застосунок, доведіть значення до 3, переконайтеся, що історія непорожня.
2. Змініть заголовок AppBar на «Мій лічильник».
3. Виконайте Hot Reload: `r` у терміналі. Напис зміниться, значення 3 та історія мають зберегтися.
4. Виконайте Hot Restart: `R`. Значення повернеться до 0, історія очиститься.

| Операція | Очікувана поведінка | Власний фактичний результат |
|---|---|---|
| Зміна напису + Hot Reload | Оновлений напис, стан збережений | Заповнити після досліду |
| Hot Restart | Новий State, нуль та порожня історія | Заповнити після досліду |

Hot Reload оновлює код та перебудовує віджети, але не створює заново існуючий State і не викликає повторно `main()` чи `initState()`. Hot Restart запускає Dart-застосунок заново. Зміни нативної Android-частини можуть потребувати повного перезапуску.

## Труднощі та рішення

- Переповнення історії: обмеження реалізоване в моделі, а не лише приховуванням зайвих рядків.
- Однаковий час кількох натискань: порядок визначає вставка на початок і унікальний id, а не сортування лише за секундою.
- Повторні повідомлення на нулі: перед новим SnackBar попередній приховується.
- Малий екран: усі елементи прокручуються в одному ListView.builder, кнопки організовані через Wrap.
- Неправильне очищення історії при скиданні: reset додає окремий запис, а не створює нову модель.
- Відсутність Android-середовища: виконуються доступні тести й вебзбірка, а Android-демонстрація залишається окремим пунктом перед здачею.
